# Task013 — Переменные в Makefile 🔍

## Что такое переменные в Makefile?

Переменные позволяют хранить значения (имена компилятора, флаги, имена файлов) и использовать их многократно. Это делает Makefile более гибким и удобным для поддержки.

```makefile
CC = gcc
CFLAGS = -Wall -O2
```

где:

* **`=`** — Присваивание с отложенным вычислением

* **`:=`** — Присваивание с немедленным вычислением

* **`$(VAR)`** — Использование значения переменной
---

## Простой Makefile с переменными

```makefile
CC := gcc
CFLAGS := -Wall -Wextra

all: clean
	$(CC) -c $(CFLAGS) *.c
	$(CC) *.o -o main

clean:
	rm -f *.o
```
---

##  Усложним Makefile

Можем выделить сборку библиотеки как отдельную цель

```makefile
FLAGS=-Wall -Wpedantic -Werror
CC=gcc

main: clear lib
	$(CC) $(FLAGS) -c main.c -o main.o
	$(CC) lib.o main.o -o $@

lib:
	$(CC) $(FLAGS) -c lib.c -o lib.o

clear:
	rm -rf *.o

.PHONY: lib clear main
```
---

## Задание 

* Запустите `make`. Убедитесь, что программа собралась.

* Создайте в директории пустой файл с именем `clean`.

* Снова запустите `make clean`. Что произошло? Почему команда не сработала?

* Удалите файл `clean` и запустите `make clean` ещё раз.

* Объясните, почему так происходит и как это связано с работой `make`.

## Решение
1) Запускаем `make`, в папке появились `main.o` и `main`: программа собралась
2) Создаем пустой файл: `touch clean`
3) При попытке запуска выводит `make: 'clean' is up to date`. В результате нужные файлы не были удалены. Почему команда не сработала:
   * Из синтаксиса Make (Task012 если нужно):
  ```makefile
	цель: зависимости
		<TAB>команда1
		<TAB>команда2
	```
	* Все цели изначально считаются именами файлов на диске. Т.е при запуске `make` Make сначала ищет файл с таким же именем, что цель (в нашем случае clean) и проверяет, обновлялись ли зависимости данного файла

	* В данном случае мы создали файл *clean*, у него нет никаких зависимостей и он не обновлялся: Make выводит, что файл не обновлялся (т.е. is up to date)/

4) Удалим файл `clean`: `rm -f clean`. При повторном запуске `make clean` всё сработает.
5) Причины, почему так происходит, уже указаны в пункте 3. Для того, чтобы избежать данной ошибки, можно добавить в верху Makefile строчку `.PHONY: clean`, и тогда Make перестанет считать цель clean некоторым файлом.
