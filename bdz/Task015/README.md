# Task015 — CMake: работа с несколькими файлами и директориями 🔍

```
project/
├── CMakeLists.txt
├── main.c
├── lib/
│   ├── CMakeLists.txt
│   ├── lib.c
│   └── lib.h
└── build/
```
---
## Разбор CMakeLists.txt

### Корневой CMakeLists.txt

| Строка | Что делает|
| :--- | :--- | 
| `add_subdirectory(lib)` | Подключает `CMakeLists.txt` из папки `lib` для сборки библиотеки |
| `add_executable(myapp main.c)` | Создает исполняемый файл `myapp` из `main.c` |
| `target_link_libraries(myapp mylib)` |Линкует программу с библиотекой `mylib` |
| `target_include_directories(myapp PRIVATE lib)` | Добавляет папку `lib` в пути поиска заголовочных файлов для `myapp` |

### lib/CMakeLists.txt

| Строка | Что делает|
| :--- | :--- | 
| `add_library(mylib STATIC lib.c)` | Создает статическую библиотеку `mylib` из `lib.c` |
| `target_include_directories(mylib PUBLIC ...)` | Указывает, что при использовании `mylib` нужно добавить текущую папку в пути поиска заголовков |

**Важно:** `PUBLIC` означает, что папка с заголовками нужна не только при сборке самой библиотеки, но и для тех, кто её использует.

## Сборка проекта

```bash
# Создание директории для сборки
mkdir build
cd build

# Генерация файлов сборки
cmake ..

# Сборка проекта
cmake --build .

# Запуск программы
./myapp
```

## Дополнительные возможности

### Добавление разных типов сборки

```cmake
cmake -DCMAKE_BUILD_TYPE=Release ..
cmake -DCMAKE_BUILD_TYPE=Debug ..
```

### Установка флагов компиляции

```cmake
set(CMAKE_C_FLAGS "-Wall -Wpedantic -Werror")
```

### Или для конкретной цели

```cmake
target_compile_options(myapp PRIVATE -Wall -Wpedantic -Werror)
```

### Добавление нескольких исходных файлов

```cmake
set(SOURCES main.c utils.c math.c)
add_executable(myapp ${SOURCES})
```

### Поиск библиотек в системе

```cmake
find_library(MATH_LIB m)
target_link_libraries(myapp ${MATH_LIB})
```

* Что произойдет, если не указать `target_include_directories` для `myapp`?


## Решение

1) Выполните всё, что написано в пункте *Сборка проекта*
2) Последняя строчка в *Сборке проекта*
3) В `ldd myapp` будет строчка `libmylib.so => (что-то там)`, т.е. динамичный линковщик на данную библиотеку.
4) Если вкратце, то для удобства. Если не вкратце, то он позволяет компилировать отдельные части программы в своих отдельных файлах CMake, т.е. создавать из них библиотеки, нужные программе, которые затем уже будут использоваться основным CMake при сборке всей программы. Если не понятно - погуглите ещё.
5) Разберем на таком примере: **Приложение** зависит от **Библиотеки А**, а та, в свою очередь, использует **Библиотеку Б**. Пусть **Библиотека А** подключает логгирование:
   * `PRIVATE`:  Даст возможность использовать это логгирование ТОЛЬКО для *Библиотеки А*: зависимая от неё **Библиотека Б** это логгирование не получит и знать о нем не будет.
   * `INTERFACE`: Обратная ситуация: **Библиотека А** не использует логгирование, но при этом **Библиотека Б** - использует, т.е. о логировании будет знать именно *Библиотека Б*
   * `PUBLIC`: Смесь `PRIVATE` и `INTERFACE`.
6) В таком случае программа, скорее всего, завершится ошибкой о том, что не был найден файл подключаемой библиотеки
